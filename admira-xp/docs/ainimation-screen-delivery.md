# AINimation → pantalla de Xpacio / Xpace screen

AINimation → Enviar a Xpacio: verifica Google, elige un Xpacio conectado y una pantalla confirmada como táctil. Preparar envío conserva una versión fija e independiente de la biblioteca. Abrir en admira.store permite revisar el recorrido; Mostrar en esta pantalla lo coloca sólo en el destino seleccionado. Abrir pantalla amplía la versión táctil. Restaurar pantalla retira la capa y deja visible la programación que seguía debajo. Las pantallas apagadas se respetan. El selector revisa automáticamente el catálogo común al abrirse: sólo asigna a táctiles con receptor conectado. Las táctiles declaradas sin receptor aparecen identificadas y bloqueadas; no se redirigen a otro Xpacio. Si el catálogo falla, avisa que la revisión no está completa. El selector sólo permite capacidad táctil confirmada; se valida también al guardar y recibir. Sin destinos táctiles aparece «Este Xpacio no tiene pantallas táctiles disponibles». El enlace permite ver esa versión: compártelo sólo con quien deba reproducirla. Cambiar el proyecto exige otro envío; los proyectos y las playlists anteriores se conservan. Hay siete receptores virtuales: tótem e iPad de Starbucks, Xtanco Barcelona, Xtanco, Xtanco Valencia, Admira Loterías y Admira Prensa. Los cinco nuevos abren su vista de pantalla por ID IoT exacto en /xpacios/pantalla/; Restaurar pantalla devuelve «Sin contenido asignado». No son superficies calibradas dentro de una escena 3D; esta conexión no acredita entrega física. Para afinar un interactivo de pantallas o zonas, pulsa Afinar en Director en el Creador: ajusta textos, posición, tamaño, colores y saltos entre marcas; Guardar interactivo y Volver al Creador conservan la película previa. Probar recorrido muestra la versión editada. Después sincroniza y prepara otro envío. El catálogo y la cesta de cafetería se editan en el Creador; animaciones, scripts y efectos adicionales se conservan como película Director.

AINimation → Send to Xpace: verify Google, select a connected Xpace and a confirmed touch screen. Prepare delivery keeps an immutable version independent of the library. Open in admira.store lets you review the journey; Show on this screen places it only on the selected destination. Open screen enlarges the touch version. Restore screen removes the layer and reveals the schedule that continued underneath. Powered-off screens are respected. The selector automatically checks the shared catalog when opened: only touch screens with a connected receiver are assignable. Declared touch screens without a receiver are identified and disabled; they never fall back to another Xpace. A catalog failure warns that inventory coverage is incomplete. The selector requires confirmed touch capability, also checked when saving and receiving. With no touch destinations it shows “This Xpace has no touch screens available”. Anyone holding the link can view that version: share it only with its intended viewers. Project changes need another delivery; previous projects and playlists are retained. Seven virtual receivers are available: Starbucks totem and iPad, Xtanco Barcelona, Xtanco, Xtanco Valencia, Admira Loterías and Admira Prensa. The five new receivers open their screen view by exact IoT ID at /xpacios/pantalla/; Restore screen returns to “No content assigned”. They are not calibrated surfaces inside a 3D scene and do not prove physical playback. To refine a screen or hotspot interactive, choose Refine in Director in Creator: adjust text, position, size, colors and marker jumps; Save interactive and Return to Creator preserve the previous movie. Test journey previews the edit. Then sync and prepare another delivery. The cafeteria catalog and basket are edited in Creator; animations, scripts and additional effects remain Director movies.

Contract: Google-authenticated `GET /api/destinations` and `POST /api/deliveries` on the existing AINimation library Worker. Creation writes only `interactive_deliveries`; no project updates. Repeated source ID + revision + content hash + destination is idempotent. Read-only unlisted `GET /api/deliveries/<64 hex>` and `/player` contain no Google credentials or owner identity. Player HTML is generated by the same validated export. The Store receiver checks exact registered location + screen ID and the fixed player origin. All iframes use sandbox `allow-scripts` and no referrer. No fleet key in the browser, no new physical command and no change to the existing 35 MCP tools.

Targets: display 1 → starbucks-wall-06; 2 → wall-05; 3 → wall-04; 4 → wall-03; 5 → wall-02; 6 → wall-01; POS → starbucks-tpv-01; iPad → starbucks-ipad-01 (wall IDs have the starbucks- prefix). Receiver parameter: `ainimation=<delivery id>`, together with `loc`, `project=starbucks`, `circuit=alsea_starbucks`, `quality=matrix`.
