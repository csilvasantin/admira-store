# AINimation → pantalla de Xpacio / Xpace screen

AINimation → Enviar a Xpacio: verifica Google, elige Starbucks Paseo de Gracia 103 y una de sus seis pantallas, TPV o iPad. Preparar envío conserva una versión fija e independiente de la biblioteca. Abrir en admira.store permite revisar el recorrido; Mostrar en esta pantalla lo coloca sólo en el destino seleccionado. Abrir pantalla amplía la versión táctil. Restaurar pantalla retira la capa y deja visible la programación que seguía debajo. Las pantallas apagadas se respetan. El enlace permite ver esa versión: compártelo sólo con quien deba reproducirla. Cambiar el proyecto exige otro envío; los proyectos y las playlists anteriores se conservan. Conexión para players virtuales del gemelo; no acredita entrega física ni incorpora otros Xpacios todavía.

AINimation → Send to Xpace: verify Google, select Starbucks Paseo de Gracia 103 and one of its six screens, POS or iPad. Prepare delivery keeps an immutable version independent of the library. Open in admira.store lets you review the journey; Show on this screen places it only on the selected destination. Open screen enlarges the touch version. Restore screen removes the layer and reveals the schedule that continued underneath. Powered-off screens are respected. Anyone holding the link can view that version: share it only with its intended viewers. Project changes need another delivery; previous projects and playlists are retained. Virtual twin players only; this does not prove physical delivery or connect other Xpaces yet.

Contract: Google-authenticated `GET /api/destinations` and `POST /api/deliveries` on the existing AINimation library Worker. Creation writes only `interactive_deliveries`; no project updates. Repeated source ID + revision + content hash + destination is idempotent. Read-only unlisted `GET /api/deliveries/<64 hex>` and `/player` contain no Google credentials or owner identity. Player HTML is generated by the same validated export. The Store receiver checks location `alsea-sbux-021`, screen ID and the fixed player origin. All iframes use sandbox `allow-scripts` and no referrer. No fleet key in the browser, no new physical command and no change to the existing 35 MCP tools.

Targets: display 1 → starbucks-wall-06; 2 → wall-05; 3 → wall-04; 4 → wall-03; 5 → wall-02; 6 → wall-01; POS → starbucks-tpv-01; iPad → starbucks-ipad-01 (wall IDs have the starbucks- prefix). Receiver parameter: `ainimation=<delivery id>`, together with `loc`, `project=starbucks`, `circuit=alsea_starbucks`, `quality=matrix`.
