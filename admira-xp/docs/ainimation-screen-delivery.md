## Native 3D binding contract · 22 October 2026

Registry: each receiver now includes `scene.item`, `scene.type` and `scene.aperture`. Four landscape receivers bind `counter` / `customer-panel`; Admira Loterías binds `turnKiosk` / `portrait-kiosk`. The legacy inventory layout IDs are retained; the scene adapter gets the real venue ID from `STORE_CFG`, not a generic default.

`life-scene.mjs` builds a named active-area mesh under the exact furniture instance and reattaches it after asynchronous Blender replacement. `ainimation-surface.mjs` projects its four actual world-space corners and rejects backfaces, occlusion and invalid transforms. `ainimation-scene.mjs` places the sandboxed delivery iframe only within that aperture and updates it with the existing render loop. Closing/retrying the view disposes the receiver before the renderer. Missing furniture disables assignment and reports the missing support; it never substitutes another screen.

`/xpacios/pantalla/` retains its stable links and embeds `/admira-xp/` with exact loc/screen, `quality=better` and `ainimationScene=1`. Existing embedded-player access rules are retained. The same-parent readiness message checks origin, source window, location and screen. AINimation delivery metadata exposes the server-registered scene binding. No credential, playlist, fleet command or physical device changes are introduced.
