Si coinciden varias reglas gana la de mayor prioridad; en empate, la última. Las reglas TPV se conservan en este navegador y dominio, por local y caja; las reglas XPL existentes se mantienen aparte. Es la experiencia del gemelo Matrix de Starbucks Alsea, sin cobro, escrituras MCP ni órdenes a TPV físico. /ifthendothat off cierra el editor. ## English

Open /ifthendothat from the CLI or IF·THEN·DO THAT in Advanced. Under IF choose I pick up a muffin or I take a muffin to the register; under DO THAT select a Pixeria song. Changing a selector saves the rule. Enable/disable, delete or add POS rules. By default, picking up a muffin plays Bad Times Deep House. Manual drag, Enter/Space and /demo tpv use the same rule once per gesture; delivery only triggers register rules. Disabling or deleting every rule leaves the muffin silent; the demo does not force a track. Stop song, Escape or /demo off stops audio and restores the previous background music volume. Editing a rule does not play it; it applies to the next muffin. The catalogue queries up to 200 Stock music items, plus the initial track; Refresh Pixeria songs queries it again, retaining cached songs if unavailable. If several rules match, higher priority wins; the last rule wins ties. POS rules persist in this browser and domain, scoped to venue and register; existing XPL rules remain separate. This is the Starbucks Alsea Matrix twin experience, with no payment, MCP writes or physical POS commands. /ifthendothat off closes the editor. With /brand starbucks the top bar shows the Starbucks logo as its identity; /brand off restores the generic brand.

## Contrato compartido / Shared contract

- XPL facts: `muffinPicked`, `muffinDelivered`; action: `playSong` with Stock ID. Engine: `XPL.evalCondition`. Only these event/action pairs are supported by the retail adapter.
- Scope: Matrix, `alsea-sbux-021`, `starbucks-tpv-01`. Storage: `xpaceos.xpl.retail.v1:alsea-sbux-021:starbucks-tpv-01`, version 1. Legacy `xpl_rules` retained. Browser/domain storage is not shared between admira.store and xpaceos.com; another open tab reports changed rules and asks for reload.
- Source: `scripts/retail-rules.mjs`, `retail-rule-composer.mjs`, existing `xpl-composer.js` and `xpl-runtime.js`; gesture snapshot prevents edits from changing a running demo.
- Catalogue: `https://api.admira.store/stock/list?type=music&limit=200`. Only type music and HTTPS media on api.admira.store / stock.admira.store; selected URLs retained offline. Initial song ID `1790706121644-y5mqrq` · Bad Times Deep House · Stock 1308.
- API: `window.XpacePOSExperience.prepareRules()`, `pickProduct("muffin")`, `demo.start/stop/state`; events `xpace:retail-rules`, `xpace:retail-song`. Sound temporarily suppresses existing background music; never modifies its playlist or advances it.
- Pending: additional products, conditions/actions, shared authenticated rule publication, physical POS integration. No new MCP write tools.

- Public read-only catalogue: `https://www.admira.store/admira-xp/music-catalog`. Fixed upstream query, reduced id/title/url metadata, no cookie or authorization forwarding. XpaceOS origins can read it without credentials.
