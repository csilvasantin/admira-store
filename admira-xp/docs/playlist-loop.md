## Playlist · Reproducir en bucle / Loop playlist

ES: En Asignar contenidos → elige pantalla o TPV → Ajustes e información aparece Reproducir en bucle, activado por defecto. Al finalizar el último contenido vuelve automáticamente al primero; con un solo contenido, lo repite. Las playlists existentes sin este campo también mantienen el bucle. Desactivarlo deja terminar la lista y se detiene al final, mostrando Playlist finalizada y sin cápsula marcada como activa.

EN: In Assign content → select a screen or POS → Settings and information, Loop playlist is enabled by default. After the last item it automatically returns to the first; a single-item playlist repeats that item. Existing playlists without this field also keep looping. Turning it off lets the schedule finish and stops at the end, showing Playlist finished with no capsule marked as playing.

ES: El cambio se guarda automáticamente en la playlist seleccionada por su #playlistUUID, con los permisos del propietario. Se aplica a los dispositivos que comparten esa playlist, sin reiniciar el vídeo actual. Si falla el guardado, el aviso No guardado conserva el borrador y la programación anterior sigue vigente. Las altas base/locales se publican como una playlist UUID al guardar. Se conserva el ajuste al añadir, quitar, ordenar, duplicar por dispositivo, recargar o volver a abrir. Recargar empieza desde el primer contenido y respeta el bucle guardado; no lo fuerza a ON. Una playlist finalizada vuelve al principio al pulsar Play. La vista previa temporal mediante arrastre sigue repitiendo su vídeo hasta Recargar; no cambia esta preferencia.

EN: The change saves automatically on the selected #playlistUUID using owner permissions. It applies to devices sharing that playlist without restarting the current video. If saving fails, Not saved retains the draft while the previous schedule remains effective. Saving a base/local playlist publishes a UUID playlist. The setting survives add, remove, reorder, split by device, reload and reopening. Reload starts at the first item and respects the saved loop setting; it does not force ON. Play restarts a completed schedule from the beginning. Temporary drag previews still repeat their video until Reload and do not change this preference.

MCP ES: XpaceOS 2.11.0 añade playlist_settings. Lee playlist_list {playlist:"#playlistUUID"} para obtener loop (booleano; defecto true) y la revisión propia de esa playlist. Luego playlist_settings {playlist:"#playlistUUID",loop:false,expected_revision:N}. Requiere clave de flota autenticada; rechaza alias base, tipo no booleano y revisión obsoleta. Usa loop:true para reactivar. No cambia contenidos, orden ni asignaciones. Los navegadores suscritos reciben el ajuste al siguiente sondeo (aprox. 5 s); un acuse de escritura no es prueba de emisión física.

MCP EN: XpaceOS 2.11.0 adds playlist_settings. Read playlist_list {playlist:"#playlistUUID"} for loop (boolean; default true) and that playlist’s own revision. Then playlist_settings {playlist:"#playlistUUID",loop:false,expected_revision:N}. Requires an authenticated fleet key; base aliases, non-boolean values and stale revisions are rejected. Use loop:true to enable again. Contents, order and assignments remain unchanged. Subscribed browsers receive it on the next poll (about 5 s); a write acknowledgement is not proof of physical playback.

Contract: owner POST /playlists and POST /playlists/<UUID> accept loop:boolean; GET returns it. Legacy owners omitting loop preserve the saved value on updates. MCP playlist_add/remove/reorder preserve it. Legacy matrix_device_layout save_playlist also accepts loop:boolean; omission preserves existing values or defaults to true for new playlists. This applies to virtual screen/POS playlists; music and AI sync retain their separate controls.
