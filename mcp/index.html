XpaceOS · Model Context Protocol

Conecta con la red XpaceOS

El puente para que agentes (silicio) y personas (carbono) se conecten a la red de retail media: ver la flota, qué emite cada pantalla en vivo, su audiencia, el proof-of-play de cada circuito y dar de alta nuevas pantallas o robots.

Endpoint

https://mcp.admira.store/mcp

Transporte: MCP Streamable HTTP · POST /mcp (JSON-RPC) · salud en GET /. Lecturas sin clave; register_device y publish_asset exigen la clave de flota AdmiraNeXT (Authorization: Bearer) y quedan firmadas por el agente. quien_soy dice quién eres. Directorio de la suite: admiranext.com/mcp.

Herramientas · 14 en v2.0.0 · red, catálogo de gemelos, XpaceScan, XPL, antena y ayuda

fleet_statusVisión general: pantallas/robots dados de alta y cuáles emiten ahora (asset + audiencia).
list_screensInventario de Xpaces activos: ubicación, id de pantalla, tipo y orientación. Filtro opcional.

register_deviceDa de alta una pantalla o robot (auto-alta) y devuelve la URL del canal para emitir.
publish_assetEl puente crear→distribuir: publica una pieza de la biblioteca de Pixeria en una pantalla (o en toda la red con broadcast explícito).
search_twinsBusca en el catálogo de 8.775 gemelos digitales por texto, marca o superficie; cada resultado trae el enlace de su gemelo (/admira-xp/?loc=id).
twin_detailFicha de un gemelo: superficies con estado, coordenadas, enlace Admira XP y reglas XPL resueltas para sus pantallas.
catalog_statsTotales del catálogo: gemelos, superficies, por marca, por tipo de superficie y por estado.
list_scenesEscenas de XpaceScan (vídeo 3D subido desde xpaceos.com/scan) con su estado y el enlace del visor.
scene_statusManifiesto de una escena: progreso de la reconstrucción, máquina, ficheros publicados, vídeo original.
xpl_rulesReglas XPL (CUANDO · PARA · ENTONCES) resueltas para una pantalla en cascada global → circuito → pantalla.
signage_feedLo último que ha salido a la red de pantallas: pieza, tipo, destino y hora.
helpLa ayuda para humanos de xpaceos.com/help, entera o por tema (gemelo, escanea, xpl, emite, alta, mcp, método).

Cómo conectar (silicio)

Claude Code, en una línea:

claude mcp add --transport http xpaceos https://mcp.admira.store/mcp

Cliente MCP con servidores remotos (config):

{
  "mcpServers": {
    "xpaceos": {
      "url": "https://mcp.admira.store/mcp"
    }
  }
}

Prueba rápida (tools/list):

curl -s https://mcp.admira.store/mcp \
 -H "Content-Type: application/json" \
 -d '{"jsonrpc":"2.0","id":1,
      "method":"tools/list"}'

Para carbono

¿Eres humano? Esto es cómo una IA se asoma a la red: pídele a tu agente que cargue este MCP y pregúntale "¿qué pantallas hay y qué están emitiendo?" o "da de alta una pantalla en <dirección>". La red responde en tiempo real.

Doctrina Xpaces · elementos

SIEMPRE En los Xpaces todos los elementos tienen que ser movibles y sustituibles.

  • Movibles: posición, escala y orientación viven en la config del Xpacio (no hardcode en el motor).
  • Sustituibles: se puede cambiar sprite / multivista / GLB / captura o el propio activo sin reconstruir la sala.
  • Aplica a: mobiliario, pantallas, sensores, figuras, NPCs, zonas de interés y cualquier pieza del gemelo.
  • Si un elemento no se puede reubicar o reemplazar desde datos → es un defecto de diseño, no una excepción.
